Дизайн, типы событий и раскладка взяты из этого макета. Я написал только код. С автором макета я не связан.

Лента всего, что происходит в вашей базе: созданные и изменённые заметки, выполненные и отброшенные задачи, Captures. Она показывает, что вы на самом деле сделали сегодня, на этой неделе или в этом году.

## Что он делает

- **Лента событий** по дням. На каждой карточке заметка, путь к ней и первые изменённые строки, так что правку видно, не открывая заметку.
- Виды **день / неделя / месяц / год** с кнопками «назад» и «вперёд».
- **Фильтры** по типу (Notes, Tasks, Captures, Canvas & snippets) и по папке.
- **Тепловая карта** последних 10 недель. Клик по дню открывает его.
- **Счётчики по типам** за выбранный период.
- **История с первого дня.** Если база лежит в git-репозитории, плагин восстановит прошлую активность по коммитам, в том числе правки, сделанные при закрытом Obsidian, другими программами или на других устройствах.
- Клик по карточке открывает заметку на изменённой строке. Cmd/Ctrl-клик открывает её в соседней панели.

Типы событий:

| Тип | Как определяется |
| --- | --- |
| Заметка создана | Новый Markdown-файл. |
| Заметка изменена | Изменились непустые строки в Markdown-файле. Правки одной заметки в пределах 30 минут сливаются в одно событие. |
| Задача выполнена | Чекбокс стал `[x]` или появилась новая строка, которая сразу отмечена. |
| Задача отброшена | Чекбокс стал `[-]`. |
| Capture | Новая заметка, путь которой подходит под одно из ваших правил в разделе Captures. Например, веб-клипы, транскрипты встреч или папка входящих. |
| Canvas и сниппеты | Изменения в файлах `.canvas`, `.base` и `.css`. Список настраивается. |

Перенос уже отмеченной задачи в другое место заметки выполнением не считается.

## Прежде чем начать

**Сначала попробуйте плагин на пустой или тестовой базе. Прежде чем использовать его на базе, которая вам дорога, сделайте бэкап.**

Плагин не должен удалять или менять ваши заметки, и я писал его так, чтобы он этого не делал. Он читает заметки и историю git, а пишет только два файла внутри собственной папки плагина: `events.jsonl` и `data.json`. Команды git, которые он запускает, только читают. Единственное исключение: `git fetch`. Он выключен по умолчанию и обновляет в `.git` только локальные копии удалённых веток.

Но я не могу обещать, что в плагине нет багов. Программа бесплатная и распространяется без гарантий. За потерянные или испорченные файлы я не отвечаю. Бэкап занимает минуту.

## Как это работает

Плагин объединяет два источника событий.

**Живая запись.** Obsidian сообщает плагину, что файл изменился, но не говорит, что именно. Поэтому при старте плагин один раз читает ваши заметки в память (займёт примерно объём заметок, но не больше 80 МБ). Когда файл изменился и после этого 60 секунд не менялся, плагин сравнивает новый текст с копией в памяти и записывает разницу. Так в ленту попадают и изменения от программ синхронизации и скриптов, пока Obsidian открыт.

**История git.** Если база лежит внутри git-репозитория, плагин читает `git log -p` при старте и каждые пять минут. Первый запуск импортирует последние 365 дней. Коммиты, которые затрагивают больше 300 файлов (массовый импорт, массовое переименование), пропускаются, а переименования без изменения содержимого игнорируются. Так появляется история до установки плагина и за время, пока Obsidian был закрыт.

**Если git отстаёт.** Если история git отстаёт от ваших файлов (например, `.git` не синхронизируется между вашими компьютерами), файлы новее последнего коммита показываются по датам изменения. На таких карточках стоит пометка «from file dates». Карточка одна на файл, с общим числом изменений, а не по карточке на каждую правку.

Если живая запись и git описывают одну и ту же правку, остаётся живая, а версия из git отбрасывается.

Всё хранится локально в `.obsidian/plugins/activity-timeline/events.jsonl`. Ничего никуда не отправляется.

## Установка и настройка

Требования: Obsidian 1.7.2 или новее на настольном компьютере (Windows, macOS, Linux). Для истории из git нужна установленная программа `git`. Мобильные устройства не поддерживаются.

1. Установите плагин: **Settings → Community plugins → Browse**, найдите **Activity Timeline**. Или скачайте `main.js`, `manifest.json` и `styles.css` из [последнего релиза](https://github.com/abbsol/obsidian-activity-timeline/releases/latest) в `<ваша база>/.obsidian/plugins/activity-timeline/` и включите плагин.
2. Откройте ленту значком «история» (часы со стрелкой) на боковой панели или командой **Activity Timeline: Open timeline**.
3. При первом запуске плагин импортирует историю git. Когда импорт закончится, появится уведомление.

Что настроить в **Settings → Activity Timeline**:

| Настройка | Что делать |
| --- | --- |
| Captures | Добавьте правило для каждого места, куда заметки попадают снаружи: префикс пути вроде `Clippings/` или `Projects/*/Transcripts/` (`*` заменяет одну папку), название и имя иконки из [Lucide](https://lucide.dev/icons/). Пока правил нет, заметки из этих мест считаются просто созданными (Note created). |
| Excluded folders | Папки, которые нужно полностью игнорировать, по одной на строку. |
| History source | По умолчанию `HEAD`. Если в этой копии базы коммиты не делаются локально, а резервируются в удалённый репозиторий (например, коммитит и отправляет их другой компьютер), укажите `origin/main`. |
| Fetch before importing | Включайте вместе с `origin/main`, чтобы новые коммиты сначала скачивались. Нужны рабочие учётные данные git. |
| Keep notes in memory | Оставьте включённым, чтобы получать фрагменты для изменений, сделанных вне редактора. Выключите, если память важнее. |
| Canvas and snippet file types | Расширения файлов, которые отслеживаются помимо заметок. |

Если ваша база лежит в git-репозитории с автоматическими коммитами, добавьте `.obsidian/plugins/activity-timeline/events.jsonl` в `.gitignore`. Файл часто меняется и восстанавливается из git.

## Раскрытие информации

- Нет аккаунта, оплаты, рекламы и телеметрии. Автору и любому серверу автора ничего не отправляется.
- **Сеть:** по умолчанию не используется. Если включить **Fetch before importing**, плагин запускает `git fetch`, который обращается к удалённому репозиторию, настроенному в вашем репозитории (например, на GitHub), с вашими собственными учётными данными git.
- **Файлы вне базы:** плагин запускает git в папке вашей базы. Если база лежит внутри более крупного git-репозитория, git читает папку `.git` этого репозитория, а она выше базы. Для событий читаются только файлы внутри папки базы.
- Исходный код плагина открыт, лицензия указана ниже.

## Ограничения

- Только компьютер.
- Без git история начинается в день установки плагина.
- Изменения от программ синхронизации и скриптов выглядят так же, как ваши. Лента показывает статистику по всей базе и не знает, кто внёс изменение.
- Из статусов задач плагин распознаёт `[x]` (выполнена) и `[-]` (отброшена). Остальные статусы игнорируются.
- Время события из git совпадает со временем коммита, а не с моментом правки.
